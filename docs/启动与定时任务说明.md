# 启动与定时任务说明

> 代码位置：`web/server.go`（`init()` + `main()`）、`codes.go`、`workday.go`、
> `web/industry.go`、`web/etf_track.go`、`web/indices.go`、`web/excalendar.go`
> 最后核对：2026-09-15（以代码为准）
> §5 为待实施的改进方案，实施前以 §1–§4（现状）为准

## 1. 启动流程（`web/server.go`）

### 1.1 `init()`：同步执行，阻塞启动

1. `tdx.DialDefault` 连接通达信服务器（失败直接 `Fatal` 退出）。
2. `tdx.NewCodesSqlite(client)` 建码表库并 `Update()`：
   沪深走 TDX `GetCodeAll` 分页拉取，北交走 `bse.cn` 爬虫。
3. `tdx.NewManage(Number=4)` 建 4 连接管理器：
   `manager.Codes.Update()` + `manager.Workday.Update()`（交易日历以 `sh000001` 日K为准）。
4. `manager.Cron.Start()` —— 注意：web 侧**没有注册任何任务**，实际空转。

### 1.2 `Codes` / `Workday` 自带 cron（各自 `New` 时注册，固定钟点）

| 任务 | 触发 | 位置 |
|---|---|---|
| 码表更新 | 每天 **9:00:10**，失败重试 3 次（间隔 5 分钟） | `codes.go:92` |
| 交易日历更新 | 每天 **9:00:00**，失败重试 3 次（间隔 5 分钟） | `workday.go:72` |

### 1.3 `main()`：四个 Init（行业/ETF 起后台预热循环，指数启动同步一次，排期起重循环）

```go
InitIndustry()    // web/industry.go
InitEtfTrack()    // web/etf_track.go
InitIndices()     // web/indices.go
InitExCalendar()  // web/excalendar.go
```

| Init | 首次延迟 | 之后动作 | 间隔 |
|---|---|---|---|
| `industryWarmLoop` | 启动后 **1 分钟** | 查缺失股票→串行补（3 秒/只；连续 5 次网络失败熔断 5 分钟） | 跑完睡 **24 小时** |
| `etfTrackWarmLoop` | 启动后 **90 秒** | 与行业抢 `warmMu` 锁（串行防限流），2.5 秒/只 | 跑完睡 **24 小时** |
| `indicesSyncFromCodes` | 启动时**同步一次** | 从 codes 提 `IsIndex` 写入 `indices` 表 | 无循环 |
| `excalHeavyLoop` | 启动后 **5 分钟** | xdxr 全市场股票+ETF（约 7835 只）全扫，约 4 分钟 | 睡 `EXCAL_HEAVY_INTERVAL_HOURS`（默认 **24 小时**） |

环境变量（`docker-compose.yml`）：

```yaml
- EXCAL_HEAVY_INTERVAL_HOURS=24
# - EXCAL_GIANT=1              # 巨潮默认停用（仅手动 refresh 生效）
# - EXCAL_TOUZID=1             # 投资数据网默认屏蔽，需同时配 TOUZID_COOKIE（仅手动 refresh 生效）
```

giant/touzid 没有自动循环，抓取函数保留，仅通过手动接口
`POST /api/ex-calendar/refresh?source=giant|touzid` 触发（见 §3）。

## 2. 定时任务总览

| 任务 | 类型 | 时机 | 说明 |
|---|---|---|---|
| 码表更新 | cron 固定钟点 | 每天 9:00:10 | `Codes.Update()` |
| 交易日历更新 | cron 固定钟点 | 每天 9:00:00 | `Workday.Update()` |
| 行业预热补缺 | sleep 漂移 | 启动 1 分钟后，之后每 24h | 缺失才补；全量后空转只打一行日志 |
| ETF 跟踪预热补缺 | sleep 漂移 | 启动 90 秒后（排在行业后），之后每 24h | 同上；被 `warmMu` 串行阻塞 |
| xdxr 排期全量 | sleep 漂移 | 启动 5 分钟后，之后每 24h | 股票+ETF 全扫，`INSERT OR REPLACE` 幂等 |

注意：

- 只有码表/日历是**固定钟点 cron**；行业 / ETF / xdxr 都是“**睡 N 小时**”，
  **重启重置计时、每天漂移**（一轮耗时越长漂得越多）。
- 重启一次会触发：1 分钟后行业预热、90 秒后 ETF 排队、5 分钟后 xdxr 全量
  （约 4 分钟打满 TDX 连接）。
- `warmMu` 含义：行业与 ETF 预热**串行**，避免并发触发 THS/东财限流。
  行业没跑完，ETF 一直等（日志可看到“预热检查”被阻塞）。

## 3. 不是自动的（手动触发）

- `web/tasks.go` 的 `TaskManager`（`POST /api/tasks/pull-kline`、
  `POST /api/tasks/pull-trade`）：**手动建任务**，无定时。
- `POST /api/ex-calendar/refresh?source=xdxr|giant|touzid`：**手动运维补数**
  （xdxr 一次 ≤50 只）。
- `scripts/import_indices.py`：**手动脚本**，扩展指数导入用，不自动跑。

## 4. 运维常用

```bash
# 看各后台循环跑到哪了
docker logs tdx-stock-web 2>&1 | grep -E "预热|排期|同步|更新" | tail -20

# xdxr 上次全量何时完成
sqlite3 data/database/excalendar.db \
  "SELECT source,last_ok,last_error FROM ex_fetch_state;"

# 手动补某几只（≤50）
curl -X POST "http://localhost:8080/api/ex-calendar/refresh?source=xdxr&codes=600519,002605"
```

## 5. 改进方案（待实施，实施后本节删除、§1–§4按新行为重写）

> 已定事项：配置方式用 `config.yaml` 文件；三个漂移任务转 cron 后默认凌晨错峰；
> 启动执行默认全关；giant/touzid **连手动部分一起全删**，只留 xdxr；
> 旧 `EXCAL_*` 环境变量直接删、不兼容。

### 5.1 目标

- 启动时每个任务跑不跑，可配置。
- 所有定时任务改为 cron 表达式，可配置（固定钟点，不再漂移）。

### 5.2 `config.yaml`（项目根，compose 只读挂载，缺失则全用代码默认）

```yaml
# cron 为 6 段式（含秒），与 robfig/cron（已在用）兼容；时区跟随 TZ=Asia/Shanghai
tasks:
  codes:      # 码表更新
    enabled: true
    cron: "10 0 9 * * *"     # 保持现状：每天 9:00:10
    run_at_start: false      # 启动默认全关
  workday:    # 交易日历更新
    enabled: true
    cron: "0 0 9 * * *"      # 保持现状：每天 9:00:00
    run_at_start: false
  industry:   # 行业预热补缺
    enabled: true
    cron: "0 0 3 * * *"      # 凌晨错峰：每天 3:00
    run_at_start: false
  etf:        # ETF 跟踪预热补缺
    enabled: true
    cron: "0 0 4 * * *"      # 凌晨错峰：每天 4:00
    run_at_start: false
  excal:      # xdxr 排期全量
    enabled: true
    cron: "0 0 2 * * *"      # 凌晨错峰：每天 2:00
    run_at_start: false
  indices:    # 启动从 codes 同步一次，无循环、无 cron
    enabled: true
    run_at_start: true       # 秒级同步，默认开，避免删库重建后空表

# 任务结果通知（成功/失败都推）
notify:
  enabled: true
  # 企业微信群机器人 webhook；key 涉密，配置文件只留占位，真 key 用环境变量注入：
  #   WECOM_WEBHOOK="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx" docker compose up -d
  # 环境变量优先于本文件；提交到仓库的本文件 key 必须为空
  wecom_webhook: ""
  only_fail: false           # true=只在失败时通知；false=成功失败都通知
```

语义：

- `enabled: false` → 该任务不注册 cron、启动也不跑（`Init` 只建表/建库）。
- `run_at_start: true` → 启动后跑一次，保留错峰延迟
  （行业 60 秒、ETF 90 秒、xdxr 5 分钟），防打满 TDX 连接池。
- 优先级：**环境变量（`TASK_<NAME>_CRON` 等）> config.yaml > 代码默认**。

### 5.4 手动执行（现状与新增）

现状：

| 任务 | 现在能否手动执行 |
|---|---|
| industry / etf | 半能：`GET /api/industry?code=`、`GET /api/etf-track?code=` 缓存未命中时实时抓**单只**，无全量手动入口 |
| codes / workday / indices | 不能，只能重启（且重启还受 `run_at_start` 控制） |
| excal | 有：`POST /api/ex-calendar/refresh`——本次一并删除，统一走新入口 |

新增统一手动入口（实施时一起做，**老 `POST /api/ex-calendar/refresh` 整个删除**，不保留）：

```text
POST /api/admin/tasks/run?name=codes|workday|industry|etf|excal|indices&codes=..(仅excal用,≤50)
```

- 按任务名派发到各任务的单次执行函数，与 cron 共用同一函数体（同样受
  `SkipIfStillRunning` 和 `warmMu` 约束，禁并发）。
- excal 的 `codes` 参数沿用老接口语义（一次 ≤50 只）。
- `GET /api/admin/tasks/status`：返回各任务 `enabled/cron/上次执行时间/上次结果`
 （读内存注册表 + `ex_fetch_state` 这类现成状态）。

### 5.5 行为变化（实施后）

1. **启动默认全关**：重启后行业/ETF/xdxr 不再自动跑，等凌晨 2/3/4 点；
   急需补数手动调 `refresh` 接口或临时开 `run_at_start`。
2. **sleep 漂移变固定钟点**：时间可预期；xdxr 约 4 分钟、行业缺失多时几十分钟，
   三者已错开 1 小时。
3. **giant/touzid 彻底没了**：库里已有 `source=giant/touzid` 的历史行不受影响
   （只读），但不再新增；以后想用从 git 历史找回。
4. **`indices` 重启默认同步**：秒级，无负担。
5. **`notify` 通知**：6 个任务每次跑完都推企业微信（含 cron/手动/启动跑）；
   推送失败不影响任务本身；真 key 必须走环境变量，**禁止提交到仓库**。
