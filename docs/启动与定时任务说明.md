# 启动与定时任务说明

> 代码位置：`web/server.go`（`init()` + `main()`）、`codes.go`、`workday.go`、
> `web/scheduler.go`、`web/notify.go`、`web/admin_tasks.go`、
> `web/industry.go`、`web/etf_track.go`、`web/indices.go`、`web/excalendar.go`、
> `tasksched.go`（根包，配置加载）
> 配置：`config.yaml`（环境变量可覆盖单个任务，见该文件头部注释）
> 最后核对：2026-09-15（以代码为准）

## 1. 启动流程（`web/server.go`）

### 1.1 `init()`：同步执行，阻塞启动

1. `tdx.LoadTaskConfig("config.yaml")` 加载调度配置（缺失/非法记日志用内置默认），
   覆盖 `tdx.CodesTask` / `tdx.WorkdayTask`，设置 `tdx.TaskDoneHook`（状态+通知回流）、通知配置。
2. `tdx.DialDefault` 连接通达信服务器（失败直接 `Fatal` 退出）。
3. `tdx.NewCodesSqlite` + `tdx.NewManage`（内含第二套 codes/workday，按任务配置决定
   是否注册 cron、启动是否更新）。
4. `manager.Cron.Start()` —— 注意：web 侧**没有注册任何任务**，实际空转。

### 1.2 `Codes` / `Workday`（`codes.go` / `workday.go`，cron 固定钟点）

| 任务 | cron（`config.yaml#tasks`） | 启动执行 |
|---|---|---|
| 码表更新 | `codes.cron`，默认每天 **9:00:10**，失败重试 3 次（间隔 5 分钟） | `codes.run_at_start`（默认 false）：为 true 才按"9点前后"条件更新，否则只从缓存加载 |
| 交易日历更新 | `workday.cron`，默认每天 **9:00:00**，失败重试 3 次 | `workday.run_at_start`（默认 false）：为 true 才 `Update()`，否则只加载本地缓存 |

`enabled: false` 时不注册 cron、不启动更新（码表仍从缓存加载保证查询可用）；
cron 非法时记日志回退内置默认。每次执行结束经 `TaskDoneHook` 回流状态+通知。

### 1.3 `main()`：四个 Init 注册到统一调度

```go
InitIndustry()    // web/industry.go → 注册 industry
InitEtfTrack()    // web/etf_track.go → 注册 etf
InitIndices()     // web/indices.go → 注册 indices（无 cron，仅启动跑/手动）
InitExCalendar()  // web/excalendar.go → 注册 excal
schedStart()      // 启动 cron
```

| 任务 | cron（默认） | 启动执行 | 单次动作 |
|---|---|---|---|
| `industry` | 每天 **3:00** | `run_at_start`（默认 false，为 true 则延迟 60 秒跑） | 查缺失股票→串行补（3 秒/只；连续 5 次网络失败熔断 5 分钟） |
| `etf` | 每天 **4:00** | 同上（延迟 90 秒） | 同上（2.5 秒/只）；与行业抢 `warmMu` 锁串行 |
| `excal` | 每天 **2:00** | 同上（延迟 5 分钟） | xdxr 全市场股票+ETF（约 7835 只）全扫，约 4 分钟 |
| `indices` | 无 | `run_at_start`（默认 true，延迟 30 秒） | 从 codes 提 `IsIndex` 写入 `indices` 表，秒级 |

cron 触发上一轮未结束则跳过（记日志）；`indices` 无 cron，只响应启动跑与手动触发。

## 2. 定时任务总览

| 任务 | 类型 | 时机 | 说明 |
|---|---|---|---|
| 码表更新 | cron 固定钟点 | 默认每天 9:00:10 | `Codes.Update()` |
| 交易日历更新 | cron 固定钟点 | 默认每天 9:00:00 | `Workday.Update()` |
| xdxr 排期全量 | cron 固定钟点 | 默认每天 2:00 | 股票+ETF 全扫，`INSERT OR REPLACE` 幂等 |
| 行业预热补缺 | cron 固定钟点 | 默认每天 3:00 | 缺失才补；全量后空转只打一行日志 |
| ETF 跟踪预热补缺 | cron 固定钟点 | 默认每天 4:00 | 同上；被 `warmMu` 串行阻塞 |
| 指数同步 | 仅启动/手动 | `run_at_start` 默认 true | 秒级同步 |

注意：

- 全部时间固定可预期（cron），**重启不再重置计时**；启动跑默认全关（除 indices），
  重启后只起服务，等 cron 时间点触发。
- `warmMu` 含义：行业与 ETF 预热**串行**，避免并发触发 THS/东财限流。

## 3. 手动触发与状态查询（运维）

- `POST /api/admin/tasks/run?name=codes|workday|industry|etf|excal|indices&codes=..`
  （`codes` 仅 excal 用，≤50 只，不传跑全市场；与 cron 共用同一函数，同样防重叠）。
- `GET /api/admin/tasks/status`：各任务开关/cron/上次触发/起止/成败/明细。
- 老 `POST /api/ex-calendar/refresh` 已删除；giant/touzid 抓取已全删，只留 xdxr 单源。

## 4. 任务结果通知（企业微信）

- 6 个任务每次跑完都推（cron/手动/启动跑全含；`notify.only_fail=true` 时只推失败）。
- 内容：任务名、触发方式、成败、明细（成功数/失败数/耗时）、时间。
- 推送失败只记日志，不影响任务；`notify.enabled=false` 或 webhook 为空则不推。
- webhook key 涉密：提交版 `config.yaml` 留空，真 key 走 `WECOM_WEBHOOK` 环境变量，
  **禁止提交到仓库**（compose 里有注释示例行）。

## 5. 运维常用

```bash
# 看各任务注册与执行情况
docker logs tdx-stock-web 2>&1 | grep -E "任务 |预热|排期|同步|更新" | tail -20

# 查状态接口
curl "http://localhost:8080/api/admin/tasks/status" | python3 -m json.tool

# 手动补某几只（≤50）
curl -X POST "http://localhost:8080/api/admin/tasks/run?name=excal&codes=600519,002605"

# 手动跑全市场排期
curl -X POST "http://localhost:8080/api/admin/tasks/run?name=excal"

# xdxr 上次全量何时完成（库侧）
sqlite3 data/database/excalendar.db \
  "SELECT source,last_ok,last_error FROM ex_fetch_state;"
```
