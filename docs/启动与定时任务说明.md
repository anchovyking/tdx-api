# 启动与定时任务说明

> 代码位置：`web/server.go`（`init()` + `main()`）、`codes.go`、`workday.go`、
> `web/industry.go`、`web/etf_track.go`、`web/indices.go`、`web/excalendar.go`
> 最后核对：2026-09-15（以代码为准）

## 1. 启动流程（`web/server.go`）

### 1.1 `init()`：同步执行，阻塞启动

1. `tdx.DialDefault` 连接通达信服务器（失败直接 `Fatal` 退出）。
2. `tdx.NewCodesSqlite(client)` 建码表库并 `Update()`：
   沪深走 TDX `GetCodeAll` 分页拉取，北交走 `bse.cn` 爬虫。
3. `tdx.NewManage(Number=4)` 建 4 连接管理器：
   `manager.Codes.Update()` + `manager.Workday.Update()`（交易日历以 `sh000001` 日K为准）。
4. `manager.Cron.Start()` —— 注意：web 侧**没有注册任何任务**，实际空转。

### 1.2 `Codes` / `Workday` 自带 cron（各自 `New` 时注册，固定钟点）

| 任务 | 触发 | 位置 |
|---|---|---|
| 码表更新 | 每天 **9:00:10**，失败重试 3 次（间隔 5 分钟） | `codes.go:92` |
| 交易日历更新 | 每天 **9:00:00**，失败重试 3 次（间隔 5 分钟） | `workday.go:72` |

### 1.3 `main()`：四个 Init（行业/ETF 起后台预热循环，指数启动同步一次，排期起重循环）

```go
InitIndustry()    // web/industry.go
InitEtfTrack()    // web/etf_track.go
InitIndices()     // web/indices.go
InitExCalendar()  // web/excalendar.go
```

| Init | 首次延迟 | 之后动作 | 间隔 |
|---|---|---|---|
| `industryWarmLoop` | 启动后 **1 分钟** | 查缺失股票→串行补（3 秒/只；连续 5 次网络失败熔断 5 分钟） | 跑完睡 **24 小时** |
| `etfTrackWarmLoop` | 启动后 **90 秒** | 与行业抢 `warmMu` 锁（串行防限流），2.5 秒/只 | 跑完睡 **24 小时** |
| `indicesSyncFromCodes` | 启动时**同步一次** | 从 codes 提 `IsIndex` 写入 `indices` 表 | 无循环 |
| `excalHeavyLoop` | 启动后 **5 分钟** | xdxr 全市场股票+ETF（约 7835 只）全扫，约 4 分钟 | 睡 `EXCAL_HEAVY_INTERVAL_HOURS`（默认 **24 小时**） |

环境变量（`docker-compose.yml`）：

```yaml
- EXCAL_HEAVY_INTERVAL_HOURS=24
# - EXCAL_GIANT=1              # 巨潮默认停用（仅手动 refresh 生效）
# - EXCAL_TOUZID=1             # 投资数据网默认屏蔽，需同时配 TOUZID_COOKIE（仅手动 refresh 生效）
```

giant/touzid 没有自动循环，抓取函数保留，仅通过手动接口
`POST /api/ex-calendar/refresh?source=giant|touzid` 触发（见 §3）。

## 2. 定时任务总览

| 任务 | 类型 | 时机 | 说明 |
|---|---|---|---|
| 码表更新 | cron 固定钟点 | 每天 9:00:10 | `Codes.Update()` |
| 交易日历更新 | cron 固定钟点 | 每天 9:00:00 | `Workday.Update()` |
| 行业预热补缺 | sleep 漂移 | 启动 1 分钟后，之后每 24h | 缺失才补；全量后空转只打一行日志 |
| ETF 跟踪预热补缺 | sleep 漂移 | 启动 90 秒后（排在行业后），之后每 24h | 同上；被 `warmMu` 串行阻塞 |
| xdxr 排期全量 | sleep 漂移 | 启动 5 分钟后，之后每 24h | 股票+ETF 全扫，`INSERT OR REPLACE` 幂等 |

注意：

- 只有码表/日历是**固定钟点 cron**；行业 / ETF / xdxr 都是“**睡 N 小时**”，
  **重启重置计时、每天漂移**（一轮耗时越长漂得越多）。
- 重启一次会触发：1 分钟后行业预热、90 秒后 ETF 排队、5 分钟后 xdxr 全量
  （约 4 分钟打满 TDX 连接）。
- `warmMu` 含义：行业与 ETF 预热**串行**，避免并发触发 THS/东财限流。
  行业没跑完，ETF 一直等（日志可看到“预热检查”被阻塞）。

## 3. 不是自动的（手动触发）

- `web/tasks.go` 的 `TaskManager`（`POST /api/tasks/pull-kline`、
  `POST /api/tasks/pull-trade`）：**手动建任务**，无定时。
- `POST /api/ex-calendar/refresh?source=xdxr|giant|touzid`：**手动运维补数**
  （xdxr 一次 ≤50 只）。
- `scripts/import_indices.py`：**手动脚本**，扩展指数导入用，不自动跑。

## 4. 运维常用

```bash
# 看各后台循环跑到哪了
docker logs tdx-stock-web 2>&1 | grep -E "预热|排期|同步|更新" | tail -20

# xdxr 上次全量何时完成
sqlite3 data/database/excalendar.db \
  "SELECT source,last_ok,last_error FROM ex_fetch_state;"

# 手动补某几只（≤50）
curl -X POST "http://localhost:8080/api/ex-calendar/refresh?source=xdxr&codes=600519,002605"
```
