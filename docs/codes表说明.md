# codes 表说明：代码分类与区分方式

`data/database/codes.db` 的 `codes` 表是**全市场代码总表**（当前 52504 条），涵盖股票、ETF、基金、债券、指数等所有品种。本文说明该表结构、数据来源，以及"股票 / ETF / 基金 / 指数"是如何区分出来的。

## 1. 表结构

| 字段 | 说明 |
|---|---|
| `ID` | 自增主键 |
| `Name` | 名称 |
| `Code` | 6 位代码（不带交易所前缀） |
| `Exchange` | 交易所：`sh` / `sz` / `bj` |
| `Multiple` | 价格倍数 |
| `Decimal` | 小数位数 |
| `LastPrice` | 最新价 |
| `EditDate` / `InDate` | 编辑时间 / 入库时间 |

关键点：**表里没有"品种类型"字段**。股票/ETF/基金/指数**不靠查表区分，而是在代码里用前缀规则硬判断**。

## 2. 数据来源

`codes` 表的数据**从通达信行情服务器拉取**（不是第三方导入），入口是 `Codes.GetCodes()`（`codes.go:203`），由 `Update()`（`codes.go:183`）触发。

### 2.1 来源分两支

| 交易所 | 来源 | 方式 | 代码位置 |
|---|---|---|---|
| 沪 `sh` / 深 `sz` | **通达信行情服务器** | `GetCodeAll` 分页请求（每页 1000 条，`GetCode` 循环拉） | `client.go:229-263` |
| 北 `bj` | **北交所官网**（通达信无北交所码表） | HTTP POST 爬虫分页（`bse.cn`），每页 100ms 间隔 | `client_bj_code.go` |

### 2.2 拉取后落库逻辑（codes.go:233-300）

- 库里已有且名字变了（如 ST 改名）→ `update`（只更新 `Name/LastPrice`）。
- 库里没有的 → `insert`。
- `sqlite3`：逐条 Insert + Update（事务）。
- `mysql`：`TRUNCATE` 后批量插入（每批 3000 条，实测约 11 秒）。

### 2.3 两种读取模式

- `GetCodes(byDatabase=true)`：**不联网**，直接读本地 `codes.db` 返回。
- `GetCodes(byDatabase=false)`：**联网**，从服务器全量拉取并增量更新库。

### 2.5 下游用法

内存 `manager.Codes.list` 里每条的完整代码（`Exchange+Code`，如 `sh600519`）供各业务筛选：

- `excalendar` 重循环调 `manager.Codes.GetStocks()`，按 `IsStock` 筛出股票，再走 `0x000f` 拉除权。
- `GetETFs()` 按 `IsETF` 筛 ETF（当前重循环未调用，见 §5.3）。

> 关键点：`codes` 表是**通达信服务器证券清单的快照**，服务器给什么就存什么（股票/ETF/债/指数全塞进来），品种区分**不靠表字段，靠 §3 的前缀规则**。

## 3. 区分方式：全靠代码前缀

分类函数都在 `protocol/unit.go`，输入必须是**8 位带前缀**代码（如 `sh600519`）。

### 3.1 股票 `IsStock()`（unit.go:250）

```
IsStock = IsSZStock || IsSHStock || IsBJStock

IsSZStock: sz + 0* (000/001/002/003) 或 sz30* (创业板)
IsSHStock: sh + 6*  (600/601/603/605/688 科创板等)
IsBJStock: bj + 8* / 43* / 92*
```

### 3.2 ETF `IsETF()`（unit.go:282）

```
IsETF:
  sh + 51/56/58*
  sz + 15/16*
```

### 3.3 其它品种

- **债券/逆回购**：`sh10-19*`、`sz1*`（国债、企业债、可转债等，如 `sh019*`、`sz127*`）
- **指数**：`sh000*`、`sz399*`
- **场外基金**：`sh50x*`（部分）、`sz16x*`
- 上述品种中，**除 `sz15*/sz16*` 会被 `IsETF` 命中外**（见 §3.2），其余在"股票/ETF"两个 `IsXxx` 里都不匹配，会被业务筛选默认跳过。注意 `sz1*` 是**大类前缀**，其中 `15/16` 属 ETF，`10/11/12/13/14/19` 等才是债券/逆回购/基金。

### 3.4 前缀补全 `AddPrefix()`（unit.go:300）

把 6 位代码补成 8 位时用它，规则与上面呼应但有遗漏（**重要，见第 5 节**）：

```
6 -> sh          (沪股票)
0 -> sz          (深股票)
30 -> sz         (创业板)
510-515 -> sh    (沪 ETF)
159 -> sz        (深 ETF)
8 / 92 / 43 -> bj (北交所)
```

## 5. 已知问题：`IsETF` 判定 与 `AddPrefix` 补前缀是两个不同层面

必须先分清两件事，之前文档把它们混为一谈是错的：

- **`IsETF()`（品种判定）**：筛选清单时用，决定"这只算不算 ETF"。
- **`AddPrefix()`（补前缀）**：把 6 位代码补成 8 位时用，决定"发请求时带不带前缀、带哪个"。

### 5.1 `IsETF()` 判定（实测逐号段验证）

按 `unit.go:282` 实际逻辑（`sh 前缀∈{51,56,58}`、`sz 前缀∈{15,16}`）逐号段实测：

| 号段 | `code[2:4]` | IsETF | 说明 |
|---|---|---|---|
| sh510/511/512/513/515/516/517/519 | 51 | ✅ 命中 | 正常 |
| sh560/561/562/563 | 56 | ✅ 命中 | **正常，非漏判** |
| sh588/589 | 58 | ✅ 命中 | **正常，非漏判（科创 ETF）** |
| sh520 | 52 | ❌ **不命中** | **唯一真实漏判**（52 段未列入） |
| sz159 / sz15x / sz16x | 15/16 | ✅ 命中 | 正常 |

结论：`IsETF` **实际缺口只有 `sh52*`**（如 520 段）。`56/58` 号段已被覆盖。

### 5.2 `AddPrefix()` 补前缀（这里是真缺口）

`unit.go:300` 只映射 `510-515 → sh`、`159 → sz`，**未覆盖**：

| 6位代码 | AddPrefix 结果 | 问题 |
|---|---|---|
| 510300 | sh510300 | 正常 |
| 159915 | sz159915 | 正常 |
| 516000 / 517000 / 519000 | 原样 6 位 | ❌ 不补前缀 |
| 560001 / 562000 / 563000 | 原样 6 位 | ❌ 不补前缀 |
| 588000 / 589000 | 原样 6 位 | ❌ 不补前缀 |
| 160105（sz16x） | 原样 6 位 | ❌ 不补前缀 |

补前缀缺失会导致拿 6 位代码直接请求失败或落到错误市场。**与 `IsETF` 判定无关**，是独立问题。

### 5.3 与"表里没有 ETF"的关系

`ex_calendar` 表里只有 stock、没有 ETF，根因是主循环：

- `excalHeavyLoop`（`web/excalendar.go:425`）只调了 `manager.Codes.GetStocks()`，**从没调 `GetETFs()`**，ETF 从未进入扫描清单。
- 这与 `IsETF` / `AddPrefix` 是两个独立环节：即使两者全对，不调 `GetETFs()` 也扫不到 ETF。

### 修复方向

1. `IsETF()` 补 `sh52*`（其余号段已覆盖，无需改）。
2. `AddPrefix()` 补全 ETF 号段：`sh` 侧 `5*` 统一加 `sh`（或明确列 `50-59`），`sz` 侧 `1*` 加 `sz`（`15/16/159` 等）。
3. `excalHeavyLoop` 改为 `GetStocks()` + `GetETFs()` 一起扫，入库时用 `type` 字段区分 `stock` / `etf`。

> 注：`0x000f` 协议（`/api/xdxr`）对 ETF 完全有效，实测 `sh510050/510300/510500/159919` 均能取到 `category==1` 的除权记录，问题只在代码清单筛选环节。
